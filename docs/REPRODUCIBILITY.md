# Reproducibility experiments

The frozen `gate20-b` configuration passed twenty exact-input probe runs across five fresh processes. The newer diagnostic runtime is repeating that gate with stronger startup evidence. Five completed 5,000-point runs have not yet passed.

## Whole-frame clock and inputs

The plugin gates Unity's main thread at `WaitForEndOfFrame`. It uses `Time.captureFramerate=60`, retains native `fixedDeltaTime=0.02`, and does not call `Physics.Simulate` or skip normal `FixedUpdate`. A loader start gate waits for a naturally occurring render update with no physics step before the native kitchen start branch proceeds. Gameplay frame zero is the first complete frame in which both server and client round behaviors are active; its remaining timer is 269.983337 because the native round has already consumed one update.

Client/server clock methods execute their original logic using a substituted logical real-time source. Clock origins vary with asynchronous loading, and native float clocks differ by small amounts. Earlier movement probes matched visible physics and gameplay at all sampled frames while differing in absolute client time. Those samples alone did not qualify exact replay.

Native `LogicalButtonBase` supplies event claims and held duration. Repeated polls of the same input state are idempotent. `ClearEvents` in native cannon session callbacks can set `m_supressUse` while use is down. Its native release reader clears the flag; a suppressed press followed by release safely restores held-use behavior. Throw/wash/chop guards use observed suppression and ordinary button inputs. No private interaction callback is invoked to perform these actions.

## Combined probe and first exact playback

`artifacts/combined-probe-a.jsonl.gz` completed 2,623 gameplay frames. It prepared a mustard hotdog and chocolate doughnut, used both cannons, delivered the hotdog, returned through a portal, washed a plate, returned it across the shared counter, and completed a chef-to-chef ingredient catch. Native delivery occurred at frame 1,175: 60 base points plus 8 tips, total 68.

A 110-frame dash/collision tail was recorded at the same paused frame with every input neutral on both sides of the boundary. `scripts/stitch_recordings.py` checks those neutral inputs and complete frame continuity and stores source hashes. The extracted 2,733-frame movie preserves requests exactly.

`artifacts/combined-exact-b.jsonl.gz` replayed that movie without feedback. Its native first delivery was again frame 1,175, with the same food, remaining-order fraction, round elapsed time and 68-point score. Raw physics and recipe state were **not identical**; see `artifacts/combined-ab-analysis.json`.

The first raw physics mismatch was a held ingredient's transient Rigidbody proxy rotation at gameplay frame 33; the chef and visible held entity still matched there. Later float differences need separate assessment from gameplay outcomes.

## Demonstrated restart RNG defect

The first implementation kept a single isolated Unity RNG stream for all native recipe calls after `Begin(seed)`. During asynchronous restart, the old kitchen could generate an order before unloading. That consumed the new stream before the new round's first order.

The source probe recorded an old-round draw at absolute frame 1, then the new kitchen's first draw at frame 606. Replay had no old-round draw and started at frame 585. Both happened to select mustard first, but their second native orders differed: source Ketchup, replay Ketchup+Mustard. Matching the first score therefore did not establish reproducibility. The initial 20-run series was interrupted after finding this defect.

The deployed correction scopes seeded RNG state to each native `RoundInstanceData` object. Old-round draws remain in the audit history and cannot consume the new round's state. The native weighted recipe generator, its mutable frequency counters and all game rules remain unchanged. A fresh native preview uses independent round data and checks that RNG, observers and live round state are restored.

The first four corrected movies completed with the same six-order prefix, delivery at frame 1,175, score 68 and final timer 224.433853. The first movie had an outgoing-round draw; the following movies did not. Full comparison of the first two (`artifacts/gate20-b-process01-run01-v02-optimized-analysis.json`) aligned all 2,736 observations: requests, gameplay events, current-round recipe RNG and native event sequence/timing matched at every observation. Strict clocks and ambient RNG differ from frame zero, and a Rigidbody proxy rotation first differs at gameplay frame 34. This evidence supports exact inputs with stable native events for those two movies; it does not establish identical raw state or complete the 20-run gate.

The second process started successfully but an immediate executable-path lookup raced process initialization. The verifier now retries identity observation and supports explicit adoption by PID, full executable path and UTC creation-time ticks. The resumed series retains the four completed movies and their immutable hashes. The previous summary is preserved; historical configuration fields absent from it are explicitly labeled rather than reconstructed as historical proof.

A second process-image lookup failure occurred before process four began any movie. The verifier now uses Windows `QueryFullProcessImageNameW` and `GetProcessTimes` on the same query-limited handle rather than the process module list. Twelve completed probes were retained; the already-created fourth process was explicitly adopted by PID and exact creation time. These were launcher identity failures, not failed native probe executions.

The cross-process comparison (`artifacts/gate20-b-cross-process-first-analysis.json`) also matches every recorded gameplay event, current-round RNG draw and native event timestamp. Quantitative drift reports cover 2,736 aligned samples per pair with no missing chef/entity identities. Maximum chef position drift is 0.000076301 world units within process one and 0.000115336 across processes one/two; maximum chef rotation differences are 0.005501 and 0.003137 degrees respectively. Internal Frankfurter Rigidbody proxy rotation differences reach 179.495 degrees while the corresponding logical food rotation differs by about 0.000084 degrees. Thus chef drift is small, but **not all raw physical proxy differences are small**. These measurements do not establish full-round replay stability.

Inspection of the maximum observed proxy rotation difference (`artifacts/maximum-proxy-rotation-explanation.md`) found that particular held proxy was kinematic and had no colliders or descendant colliders. The attached logical food's rotation matched at the maximum-difference frame. Native held-item synchronization copies proxy position while leaving its rotation stale; normal dropping overwrites proxy rotation before physics reactivates. The exact earlier rotation write was not traced, so this is a bounded explanation for the inspected proxy, not a general claim that all physical differences are harmless.
