# Native authoring parity acceptance

This is an acceptance plan, not a claim that the migrated framework has full rewind parity. An offline checkpoint test proves its managed contract only. Each row below needs an actual native checkpoint, an ordinary-input continuation, two fresh restores of that checkpoint, and comparison of every observed continuation frame. Final high-score qualification additionally requires fresh-start, no-warp runs.

Every experiment must retain plugin/host/source/game-assembly hashes, native process and round identity, original and replay input recordings, accepted payload and neutral-release frame counts, actual restore acknowledgment, and failure/neutralization receipts. Compare raw output before choosing any projection. A target frame tag or remembered controller history is not evidence of native restoration.

The strict report should keep these independent comparisons:

1. Accepted four-chef input payloads, edge states and all native frame counts, including the two authored neutral-release frames.
2. Authoritative native round/food/progress/ledger state. A named gameplay projection may remove only declared authoring diagnostics such as the warp-attempt count; preserve their raw values.
3. Native entity pose/velocity/attachment data, initially with actual IDs. A separately named logical-path projection may account for native allocator-selected replacement IDs and their physical proxies. It must reject ambiguous paths, unknown/missing objects and unmatched children.
4. Native sidecar state and lifecycle evidence: global clock floats, cooldown/use state, cannon fields, pending returns and ordinary callback ordering. Controller simulation history cannot stand in for a missing observation.

Current source gaps that remain material are PhysX internal contact/sleep/accumulator state, native synchronization/interpolation state, active cannon coroutine/session state, Unity-owned delivery coroutine waits, and unverified active portal transitions. The first native F tests already demonstrated why the distinctions matter: a short movement continuation and an order-generation continuation matched, while pickup cooldown and initial attachments exposed separate omissions. Later isolated idle improvements do not prove cooking, washing, transport or a full round.

Paused responsiveness has a concrete source cause: `InjectorServer.CurrentInput` can call `BlockingQueue.Dequeue(TimeSpan.FromSeconds(2))` from Unity `ControllerHandler.LateUpdate`; `Monitor.Wait` blocks that thread, including its next bridge/window pump. The proposed correction is a nonblocking reply pump **only while already authoring-paused**, keeping exactly one outstanding exchange and no new accepted frame until its reply arrives. It must preserve pause/resume phase alignment and must not commit duplicate or invented frames. Logging deduplication/caps address disk growth separately; they do not remove this main-thread wait.
