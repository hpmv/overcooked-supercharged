# Registered rigidbody and transform checkpoint

The historical pose-only implementation below is extended for the next candidate by [automatic mass-frame restoration](FRAMEWORK-AUTOMATIC-MASS-RESTORE.md), grounded in native V's successful pickup followed by preflight rejection. That new source has offline validation; native reset/replay parity is still untested.

The native-P movement probe restored all reported rigidbody physics fields, but chef103's pickup/placement highlights differed. A stale `Transform` is a source-grounded hypothesis: `GroundCast.FindGround` reads `m_Transform.TransformPoint`, and interaction searches run after pose restoration. A rigidbody pose receipt alone does not prove that the transform used by those searches matches.

`framework/patch/NativeBodyPoseCheckpoint.cs` captures both actual native representations for each selected initial registered Rigidbody: body world position/rotation and transform local/world position/rotation, with exact registry entry, GameObject, Rigidbody, Transform and parent references. The initial native registry defines the ID set; later captures ignore extra dynamic bodies and reject missing/replaced fixed bodies or changed parents. An independently registered physical proxy is captured once through its own Rigidbody, rather than traversed again through an item's attachment.

Restoration validates the entire selected set before writing, sets captured local transform pose first, then captured body pose, and skips already-equal assignments. It changes no velocity, kinematic flag, parent, clock, input or broad scene hierarchy. Verification compares all six captured pose values without an epsilon. Native Unity may expose different body and transform positions at the same boundary; the helper preserves that difference rather than deriving one from the other.

The root integration places restoration before the existing chef/GroundCast pass and performs final restore/verification after the other checkpoint sidecars. `Diagnostics` provides separate body, local-transform and world-transform fields. The helper itself does not call `Physics.SyncTransforms`, simulate physics, or recompute interaction targets.

`artifacts/framework-body-pose-tests.json` records24 production-helper checks using deliberately independent Rigidbody/Transform stand-ins: ordering, unequal poses, selected-body membership, replacement/deletion, changed parent, whole-set preflight, dynamic exclusion, nonfinite values, zero quaternion fields and diagnostics. A full installed CLR2 plugin compile passed to `artifacts/framework-body-pose-check/SuperchargedPatch.dll` before root integration. These checks do not establish actual Unity setter timing.

The subsequent native-Q2 movement and nominal pickup-input probes passed restored-baseline and replay entity, round, food and raw-physics comparisons, including both transform poses and restored interaction highlights. Their closed receipts are `artifacts/framework-migration/native-q/{movement-probe,pickup-probe}/summary.json`. A later explicit outcome audit found that Q's pickup inputs did not actually transfer plate12: it remained on counter41 in both continuations. This proves matching input continuations only, not successful pickup replay. The correction and unchanged source-evidence hash are in `pickup-probe/requested-outcome-audit.json`. The idle probe's second restored baseline still differs in sleep bits on15 persistent kinematic bodies; its original and both final replay raw-physics receipts match. See `FRAMEWORK-PAUSED-SLEEP.md`; no all-state or complete-round parity claim follows.
