# Native S body rotation roundtrip

This report preserves the S/T hypothesis and original constraints. Native V later demonstrated a legitimate carried-shape mass change. The separately documented [automatic mass-frame restoration](FRAMEWORK-AUTOMATIC-MASS-RESTORE.md) now permits topology-verified native resets for the next candidate; the earlier no-reset experiment below remains historical evidence.

The S pickup checkpoint failed exact body restoration on chef 103. At frame 491 the saved Rigidbody quaternion was `(0, -0.7071068, 0, 0.7071068)`. After restoring it, the getter returned `(-8.318395e-10, -0.7071068, -1.86264515e-9, 0.7071068)`. Local and world Transform rotations still matched the saved quaternion. This is a strict failure; no tolerance or sign normalization was applied.

Evidence is retained in `artifacts/framework-migration/native-s/pickup-probe/observations.json` and `pickup-failure-native.json`. The mass/inertia frame was not included in those historical receipts, so its contribution is not yet demonstrated.

NVIDIA's public PhysX 3.4 implementation normalizes an actor pose before multiplying it by the body's mass-local pose in `setGlobalPose`. The getter multiplies the stored body-world pose by the inverse mass-local pose. Those floating-point compositions can make a getter/setter roundtrip nonidentity; scalar normalization alone cannot introduce nonzero x/z into an input having both zero. This is a source-grounded hypothesis, not a claim that the installed Unity native binding uses exactly this public revision. [Setter](https://github.com/NVIDIAGameWorks/PhysX-3.4/blob/master/PhysX_3.4/Source/PhysX/src/NpRigidDynamic.cpp#L62), [getter](https://github.com/NVIDIAGameWorks/PhysX-3.4/blob/master/PhysX_3.4/Source/PhysX/src/NpRigidDynamic.h#L70).

The installed `UnityEngine.PhysicsModule.dll` exposes read access to mass, centerOfMass, worldCenterOfMass, inertiaTensorRotation, inertiaTensor, constraints, interpolation and the ordinary body pose/physics flags. `artifacts/framework-rigidbody-api-audit.json` records the Cecil metadata inspection. A search of the provided native game C# tree found no writes to the COM/inertia properties. Unity 2017.4 documents automatic inertia rotation calculation from attached colliders; its value must therefore be observed rather than assumed identity. [Unity inertiaTensorRotation](https://docs.unity3d.com/2017.4/Documentation/ScriptReference/Rigidbody-inertiaTensorRotation.html).

For the next authoring experiment, capture those invariants at baseline and before/after restoration. Do not call ResetCenterOfMass/ResetInertiaTensor, change constraints, toggle kinematic state, or step physics to force a matching getter. Changing the mass-local pose itself rewrites body-world state and can update a kinematic target in the public PhysX implementation. [Mass-local pose implementation](https://github.com/NVIDIAGameWorks/PhysX-3.4/blob/master/PhysX_3.4/Source/PhysX/src/NpRigidDynamic.cpp#L142).

A narrowly bounded setter-preimage experiment could adjust only the explicit authoring rotation assignment: at most four attempts, adding the observed readback residual to the previous candidate. It must record each candidate and readback, reject nonfinite/stagnating/worsening or excessive residuals, and accept only exact saved body and Transform poses with unchanged physics invariants and clocks. Exact preimage existence is not guaranteed. Public pose equality still does not prove equal internal PhysX body-world storage or contact caches; replayed native continuation remains required. No restoration code or game state was changed by this audit.

## T source experiment

After the read-only audit, the approved `NativeBodyPoseCheckpoint` implementation adds the bounded setter-preimage experiment. Four assignments total are permitted per mismatching body; both candidate displacement and readback residual must stay within `1e-6` per component. This bound admits a candidate search, not an approximate success: all four final body quaternion components and all other captured poses still use the existing exact field comparisons. No manual normalization or quaternion sign change is used. Each setter input, readback, residual and error is retained in `LastRotationRestores`, with a restore-call serial and an explicit count if the bounded 256-row history drops older records.

Mass, center of mass, inertia tensor/rotation, drag, angular drag, constraints, interpolation, collision detection, sleep threshold and maximum angular velocity are captured and checked without writing those properties. The velocity, angular velocity, kinematic and gravity values at each restore call must remain unchanged. Preflight currently compares saved settings against the current body before attachment restoration; it can conservatively reject a legitimate compound-collider mass-property change. Native T evidence is required before changing that timing.

The linked production fixture suite passes 81 assertions, including a two-assignment residual model, no redundant setter for an exact body, rejection of irreducible tiny error, four-attempt exhaustion, nonfinite readback, settings changes and setter side effects. The full source compiled against installed CLR2/Unity assemblies. Evidence: `artifacts/framework-body-preimage-tests.json`, `artifacts/framework-body-preimage-check/SuperchargedPatch.dll`. These are offline policy and compatibility checks; the installed setter's invertibility and replay parity remain unverified by this source experiment.
