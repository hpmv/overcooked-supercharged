Residual physical risks are source findings, not demonstrated failures requiring speculative corrections:

1. `ActiveStateCollector` reads Transform poses, while native `RigidbodyMotion.GetPosition/GetRotation` read Rigidbody poses. `WarpChefAndPositions` sets Transform pose plus Rigidbody velocity. If a future actual trace first diverges here, capture both poses and the physical-container parent identity, then restore the authoritative Rigidbody pose only in explicit authoring. Do not replace observed world pose with a guessed normalized value.
2. Rigidbody sleep, kinematic/interpolation state, pending forces/MovePosition work, and PhysX contact caches are not a complete part of the current generic checkpoint. Native movement applies gravity and uses `Rigidbody.MovePosition`; a pause between Update and a later FixedUpdate can retain pending work. A bounded support gate or measured shadow record of that actual work is safer than assuming pose+velocity is a full engine checkpoint.
3. `GroundCast.ForceUpdateNow` recomputes contacts and can emit ground-change callbacks. Native GroundCast itself avoids updates while sleeping. `SurfaceMovable` retains current/previous moving-surface references and cached velocity. A demonstrated moving-surface mismatch would need those exact fields and identity checks; recomputing them is not automatically equivalent.
4. `ServerPhysicalAttachment.Attach/Detach` changes parent/local pose, kinematic state, prediction flags, and native callbacks. Its detached physics container is a distinct Rigidbody object. Existing exact unchanged-attachment paths should remain no-ops. Any future physical sidecar must identify the actual container, not just the visible food entity.
5. Restored native world synchronization and interpolation keep their own paused/parent/last-server state. General restoration is still unverified. The separate steady-cannon-flight work owns its passenger synchronization fields and must not conflict with a future generic sidecar.
