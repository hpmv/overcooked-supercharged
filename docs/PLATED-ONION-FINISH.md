# Optional plated onion finish

`--plated-onion-finish` enables `CarnivalPlannerOptions.PlatedOnionFinish`; the default is false. For a selected native onion-cooking obligation, an idle central chef may take a real clean plate, assemble its already completed plain hotdog, add zero or one condiment, consume the exact cooked onions from their original pan, then place the finished plate on the selected lower-right output. The original pan is never lifted. Failed admission retains the existing unplated harvest or whole-pan rescue path.

## Admission and ownership

Admission is restricted to the existing selected `EarlyOnionLease` in Heating with no owner, an exact normal-Pending onion recipe with at most one condiment, and an exact already prepared unplated plain base. It requires native pan cooking duration12, finite progress in9–18 seconds, the pan still on its original stove, and the original reserved parking counter empty. An idle controlled, stationary, empty-handed central chef must pass the existing participant and native-input guards.

The plate must be an actually available clean token with an unowned native source. Existing FIFO plate allocation and output policy apply, and the output must be in lower-right. If this is the only clean token, any earlier Pending meal that admits ordinary assembly using the same exact plate prevents this later onion allocation. The shared read-only ordinary inspector covers ready donuts and hotdogs as well as the previous two-condiment case; it returns before reservations, callbacks or Work creation. With two available clean tokens, parallel allocation remains permitted.

The new Work owns the base, its source, exact plate, output and any required dispenser/switch. The existing persistent onion lease alone owns pan, stove and unused parking counter. The plate's initial counter must be free at admission but is not locked throughout the whole trip, allowing a successor after native pickup. The base source remains owned until final completion. No Work or input edge is preempted. The separate `PlatedFinish` phase preserves all other onion phase callbacks.

Before admission, collision-aware paths include any required empty-handed switch, plate pickup, base assembly, condiment, original pan and output. ## Observable completion

The observer pins active station and plate ordinals plus the base food's native registration sequence, Unity instance identity and observed ordinal. It proves exact empty-plate pickup before assembly, allows only the observed same-plate recovery at the original base counter, and requires a matching source removal receipt within three advancing gameplay frames of native base acquisition. It accepts the proven inactive-source/removal lag, not arbitrary source disappearance or native ID reuse.

Before onion consumption the exact held plate must have the correct plain base and zero/one condiment. Native Cooked evidence for the owned onion batch must precede the pan becoming empty. Consumption requires the same held plate's exact full recipe, the pan's reset progress, and the original pan still on its stove.
