# Native automatic mass-frame restoration

Native V successfully picked up plate12 with chef103, then rejected authoring rewind before mutation because the future carried shape changed the chef's center of mass and inertia rotation. The saved frame71 COM was `(0,1,0)`; the future COM was `(5.077871e-8,0.9786162,0.0347954)`. Saved inertia rotation was `(0,0,0,1)`; future rotation was `(-0.03384552,7.685589e-7,-2.602719e-8,0.9994271)`. The physical proxy121 also changed its COM and inertia tensor. The unchanged native receipt is `artifacts/framework-migration/native-v/pickup-failure-native.json`. V's successful pickup is not a successful pickup rewind or replay.

The new source for the next isolated candidate separates restorable mass properties from immutable settings. A future COM, tensor, inertia rotation or mass change no longer fails preflight solely because its numbers differ. Exact registered body/object/transform/parent identity, finite values, and drag, angular drag, constraints, interpolation, collision detection, gravity/velocity preservation and other settings remain guarded. A read-only `before-preflight-body-validation` stage now records the future state even when validation subsequently fails.

Before recomputing mass properties, native attachment callbacks must have restored the saved compound collider membership and every saved collider incarnation. The guard checks analytic shape dimensions, parent chain, ancestor local pose/scale/activity, actual active-in-hierarchy state, enabled/trigger/layer flags and shared material identity. Reading `sharedMaterial` does not instantiate a material. Mesh collider identity is recorded for pose verification, but mass recomputation rejects meshes because mutable vertex contents are not captured. A saved dynamic collider deleted and recreated under a different incarnation also requires a separate, explicit remap; this helper does not infer one.

The helper restores captured Transform and Rigidbody poses before invoking `ResetCenterOfMass()` and `ResetInertiaTensor()`, once each per affected body in a restore pass. It restores mass only when necessary. It never assigns COM, tensor or inertia rotation numerically. Both native resets must reproduce the saved numeric mass properties; a mismatch fails with its actual readback. There is no tolerance or manual fallback. A provisional quaternion setter before reset counts toward the existing maximum of four rotation assignments; every final pose remains subject to exact component comparisons. Immutable settings, velocity, angular velocity, kinematic/gravity flags and collider geometry must remain unchanged through the reset.

Unchanged-mass early pose restoration retains its existing position before the cannon sidecar; it does not require future cannon child poses to have been restored prematurely. Final verification, after the cannon sidecar, checks the full saved collider topology. An affected body whose target geometry is not yet restored is rejected before mass recomputation. No simulation tick, clock correction, wake/sleep change or physics synchronization call is introduced.

Unity 2017 documents that manual mass-property setters disable automatic calculation and that resets restore automatic updates. The source therefore uses resets rather than numerical setters. [ResetCenterOfMass](https://docs.unity3d.com/2017.4/Documentation/ScriptReference/Rigidbody.ResetCenterOfMass.html), [ResetInertiaTensor](https://docs.unity3d.com/2017.4/Documentation/ScriptReference/Rigidbody.ResetInertiaTensor.html), [inertiaTensor](https://docs.unity3d.com/2017.4/Documentation/ScriptReference/Rigidbody-inertiaTensor.html).

Automatic-mode provenance is bounded. `artifacts/framework-native-mass-mode-api-audit.json` records zero COM/inertia setter or reset call sites across the installed managed game DLLs, and no automatic-mode getter in the installed Unity API. Harmony observes all three managed manual setter wrappers from plugin startup; any observed manual assignment disqualifies that body, even after a subsequent reset. Capture checks that these observers are installed. The user's extracted cannon prefab has no serialized COM/tensor/mode fields, but that older extracted asset is supporting evidence only, not an installed-asset or private native-mode proof. Native engine calls or serialized private flags cannot be ruled out by the managed audit. A same-recording pickup/drop continuation is still required to test automatic recomputation behavior.

`nativeCheckpoints.nativeBodyMassFrameRestores` reports the policy, observed manual-body count, bounded reset receipts with before/target/after values, and exact outcomes. `requestedBodyCheckpoint` includes captured collider geometry; `nativeBodyWarpStages` retains the phase-specific observations. Historical raw failures are unchanged.

Offline validation: `artifacts/framework-body-auto-tests.json` links 141 production-helper assertions to the actual V receipt and source hashes. Controlled Unity stand-ins model native reset responses; they prove admission, rejection, ordering, bounded assignment and reporting policy, not native PhysX recomputation or full rewind parity. The source also compiles against the installed CLR2/Unity assemblies in `artifacts/framework-body-auto-check`; `artifacts/framework-body-auto-compile.json` pins every consumed source file and the resulting DLL. W may use an earlier immutable build; only a later build manifest containing these exact sources can claim this implementation. No native run was performed by this subtask.
